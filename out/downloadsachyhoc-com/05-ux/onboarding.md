# Onboarding — path to first value

First value = **downloading a needed book**. With **no tiers and no payment**, the path is short and
uniform: register (username + password) → download anything. There is no purchase, no activation
step, no "which tier" decision.

## The on-site journey (target)
| # | Step | Screen | Notes |
|---|---|---|---|
| 1 | Arrive from Google on a book page | Book detail | most entries are SEO, not homepage (observed IA) |
| 2 | Click "Tải sách" | Login modal (if anon) | OBSERVED — first stop |
| 3 | Register or log in — **username + password only** | Login/Register modal | one short form; no Google |
| 4 | Download resumes automatically | Book detail | **instant first value — any book** |
| 5 | Return, log in, re-download | My library | repeat value (Bet 2) |

## Where users could get stuck
- **The modal losing your place.** After register/login the download must resume on the same book —
  don't bounce the user to an account page. (interaction-rules.md)
- **Registration friction.** Keep it to username + password (+ email for reset). No profile fields,
  no email verification wall before first download unless abuse (R7) forces it.

## Rebuild implication
There is no tier gate to design and no off-site acquisition to explain — the whole funnel is
"click download → register → get the file." Make that two-tap path frictionless and make My library
the reason to come back (Differentiation Bet 2). Verify the gate + delivery (R1) via the BRIEF.
