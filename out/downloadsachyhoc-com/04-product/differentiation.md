# Differentiation — downloadsachyhoc-com

Goal is parity, so bets are deliberately few and modest — places where the reference's own
weaknesses (old stack, orphaned browse, ambiguous gating) are cheap to beat without expanding scope.
(Payment/activation is out of scope — no on-site purchase — so the former activation bet is dropped.)

### Bet 1 — Findability of the deep catalog
Bet: make the 79-category / 666-author catalog navigable in ≤2 clicks to any book.
Evidence: reference buries books at taxonomy depth 4 and leaves 666 author archives with no nav
entry (sitemap.md depth warning; orphan-routes.md).
Measurable: reference = up to 4 clicks (tree) + authors unreachable from nav; target = **≤2 clicks
to any book** via faceted filter + author A–Z index + instant search.
Cost: a proper search/filter index (more than WOOF's admin-ajax) to build and maintain.

### Bet 2 — Trustworthy download experience
Bet: a clear, honest download center where a logged-in member re-downloads anything reliably — and
where the login prompt is the *only* thing between a visitor and a book.
Evidence: reference gates via a login modal AND an inferred per-book tier note ("2nd note line"),
so a visitor can't tell whether a click will actually give them the book; delivery mechanism
unverified, "unlimited" semantics unclear (coverage.md; features: protected-delivery).
Measurable: reference = ambiguous (login gate + a per-book tier note that may still deny you);
target = **one honest rule — logged in ⇒ every book downloads — surfaced as a single "My library"
view of everything you've taken, 0 dead-end clicks, 0 "you need a higher tier" walls**.
Cost: reliable protected delivery + a download-history table. Simpler than the reference (no
entitlement model to build), so the bet is mostly about honesty and reliability, not new machinery.

Not bets (explicitly): visual polish, "better UX" in the abstract, more content. Parity first.
Removing tiers is a *scope* decision, not a differentiation bet — it makes the product simpler, not
distinctively better, so it is not counted here.
